  - [ ] CI grep on `paid version|pro tier|premium tier|locked|unlock|upgrade to|monetization|paid plan` returns 0 hits across customer-facing files (PR 8 task).

## Guideline 7 — No tracking without consent

- [x] No opt-in usage telemetry in v1.0.0.
- [x] DNT / GPC / WP Consent API honoured — Recorder writes attribution=NULL when consent is declined, revenue still counted (anonymous accounting).

## Guideline 11 — No hijacking the admin

- [x] No global admin nags.
- [x] Single dismissible activation notice (existing pattern).
- [x] All Statnive CSS/JS scoped via `#statnive-app` selector + `ReactHandler::HOOK_SUFFIXES` enqueue gate (admin asset scoping rule).

## Capability / REST

- [x] Every REST endpoint uses `Capability::can_view_reports()` (= `view_woocommerce_reports` ∨ `manage_options`).
- [x] No endpoint uses `__return_true`.
- [x] Every endpoint has args with `validate_callback` + `sanitize_callback`.
- [x] Every dynamic SQL uses `$wpdb->prepare()` (table-name interpolation is from constants only; sniff is silenced with documented `phpcs:disable` blocks).

## Database

- [x] All 26 Statnive tables documented in `readme.txt` "Database tables" section (to be updated in PR 8).
- [x] dbDelta-safe schema definitions (lowercase types, 2-space indent before PRIMARY KEY, no foreign keys per existing convention).
- [x] Migration runner has upper-bound guard so v1.0.0 migrations skip on test harnesses pinned to lower STATNIVE_VERSION.
- [x] Per-site email pepper seeded on activation; never rotated; autoload=no; never exposed via REST.

## Uninstall

- [x] `uninstall.php` honours the opt-in `statnive_delete_data_on_uninstall` (default OFF) — safer than the previous always-destroy behaviour. Existing v0.4.13 users who delete + re-install now keep history.
- [x] Cron hooks always cleared regardless of opt-in.
- [x] GeoIP files always cleaned up.
- [x] Multisite-aware (per-site cleanup + sitemeta cleanup).

## WooCommerce safety (the user's explicit "never touch WC data" directive)

- [x] Recorder is READ-ONLY against WC — only calls `$order->get_*()` getters.
- [x] No writes to `wp_posts`, `wp_postmeta`, `wp_wc_orders`, `wp_wc_order_addresses`, etc.
- [x] HPOS + Block Checkout compatibility declared via `FeaturesUtil::declare_compatibility` at `before_woocommerce_init`.
- [x] Every WC hook callback routed through `SafeHook::wrap()` — any Throwable is caught + logged to `statnive_failed_requests` + swallowed. WC's order flow can never be interrupted by a Statnive bug.
- [x] WC 8.5+ Order Attribution meta read via `$order->get_meta()` (read-only). Never `update_meta_data()`, never `delete_meta_data()`.
- [x] Soft-delete via `deleted_at` column — `woocommerce_delete_order` never causes Statnive to lose history.
- [x] Verified via `mysqldump` snapshot before+after a test order: zero changes to any WC table.

## Backward compatibility for existing users (v0.4.13 → v1.0.0)

- [x] `HOOK_SUFFIX` constant on `ReactHandler` kept as a back-compat alias (defensive against external callers).
- [x] Existing `manage_options` administrators still see the menu (cap chain).
- [x] Shop Managers gain access (intended behaviour, documented; sites can opt out via `statnive_view_reports_caps` filter).
- [x] Existing analytics tables coexist with the 5 new WC tables — no destructive migrations.
- [x] `statnive_db_version` upper-bound guard prevents stale-test-bootstrap edge cases.

| Pattern | Match | Allowed exception |
|---------|-------|-------------------|
| `\bpro tier\b` | block | n/a |
| `\bpremium tier\b` | block | n/a |
| `\bpaid plan\b` | block | n/a |
| `\bupgrade to\b` | block | n/a |
| `\bunlock(?!ed)\b` | block | n/a |
| `\bgrowth tier\b` | block | n/a |
| `\bmonetiz` | block | n/a |
| `Paid Search` | allow | channel taxonomy |
